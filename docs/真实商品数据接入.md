# 包懂你：真实商品数据接入

当前内置记录为模拟电商商品资料，不等同于已核实的电商商品库。当前内置64款使用完整且固定的模拟规格、店铺、服务、好评率与评价，页面底部统一说明一次。回答、卡片、对比表和详情共享同一份数据，模型可以依据这些记录完成选款体验；它们不代表真实品牌的销量或性能。真实导入记录不会自动补造这些字段。

## 最短操作流程

1. 从公司商品库、商家导出文件或获授权的电商接口取得数据。不需要把整个数据库交给模型。
2. 参考本目录的 `products-template.json`，将每个商品整理为一条记录。把示例占位文本替换为真实资料；不知道的数值用 `null`，不要填0代替未知。
3. 保存为 `bag_products.json`，放到仓库根目录，和 `bag_local.py`、`bag_engine.py`、`start.py` 同级。不要上传密钥、客户信息或没有公开授权的商业资料；私有数据应在服务端通过数据库或授权接口读取。
4. 若要只使用真实录入商品，在 Render → Environment 增加 `BAG_CATALOG_ONLY`，值填 `1`。不设置时，录入数据与原有内置资料共同展示。
5. 提交文件后在 Render 部署最新提交，网页新建对话。当前 JSON 方案在启动时加载；价格和库存更新后须更新文件并重新部署。

真实数据模式若没有有效商品，会展示空商品库，不偷偷退回模拟库。名称和 HTTPS 商品链接是必需字段。

## 字段

- `name`：展示标题；`sku`：来源SKU；`family`：同系列去重标识；`brand`：品牌。
- `url`：该SKU准确详情链接，不能用搜索页冒充；`image_url`：该SKU获授权的 HTTPS 主图。
- `price`、`sales`、`rating`（百分比）、`review_count`：有来源才填，避免混淆月销、累计销量和评价数。
- `weight`（克）、`capacity`（升）、`laptop`（英寸）、`dimensions`、`material`：商家明确参数；电脑标称尺寸不保证实际内仓适配。
- `source`、`updated_at`：平台、店铺、采集日期及统计口径。
- `aesthetic_tags`：可选 `清新少女`、`酷感机能`、`极简`、`复古`、`运动感`、`商务`、`活力撞色`；应按对应SKU图片标注，而不是按品牌批量推断。
- `categories`：通勤电脑双肩包、学生护脊书包、休闲双肩包、户外登山包、托特包、斜挎包、胸包。
- `feature_flags`：宽肩带、电脑隔层、胸扣、行李箱插带、防盗口袋、水杯侧袋、背部透气、少分区。只有已确认才填 `true`，确认没有填 `false`，未知填 `null`。
- `water_protection`：防泼水、日常防雨、有防水证明；未知用 `null`。不能把防泼水自动当作长时间淋雨防护。
- `scene`、`style_tags`、`color`、`advantages`、`limits`、`reviews`：对应实际规格及可追溯评论；不得生成好评来补充口碑。

## 正式上线推荐

由后端使用公司商品数据库或电商授权接口，先按预算和功能筛选，再让模型解释候选结果。详情链接、图片、价格从同一SKU读取，定期更新库存与价格。主图失败时不应替换成无关商品。

JSON方案适合小规模作品演示；数据库查询、自动同步库存/价格、CSV自动导入、电商链接解析，目前均未实现。网页的购物车是本作品的商品收藏及提问清单，不会同步京东或淘宝账号，也不能支付。

模型接口密钥仅配置在 Render 服务端环境变量 `BAG_AI_KEY`。公开访问者发送AI问题会消耗该密钥所属账户的Token；只浏览页面、加入购物车、选择提问对象不会调用模型。长期公开应增加访问限制、调用频率及费用上限。
