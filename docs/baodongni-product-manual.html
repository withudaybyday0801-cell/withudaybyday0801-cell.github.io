1. 产品定位与使用方式

包懂你是一款以背包为主要品类的对话式导购助手，帮助消费者将“夏天背、轻一点”“上班用、不要太大”等日常表达转化为选款方向，再通过少量追问明确需求。也支持针对已选商品提问和比较，辅助决策。

打开网页后，可直接输入需求，或点击“选品推荐”开始。按提示补充场景、装载物品、必要尺寸与预算；查看匹配商品后，可进入详情，或加入购物车再选定商品提问。需要重新开始时点击“新对话”。

示例：“上班用，不带电脑，200 元以内”→按通勤场景和预算筛选，重点说明日常收纳，不默认需要电脑仓。“这款可以手提吗”→先回答是否可以，再补充提手形式。

商品分析与问答选定一款，查看特点与使用边界；询问防水、肩带、透气、手提、容量、电脑适配等具体问题。

商品详情与评价查看关键参数和正面、侧面、背面图片；浏览部分评价。外部入口按实际资料标明详情链接或同名搜索。
多轮澄清补充、修改或取消条件；推荐阶段每轮追问一个关键问题。单品问答与比较直接回答当前问题。
历史记录在当前浏览器保留会话，支持查看历史或开启新对话；不自动跨设备同步。

3. 对四项“提示思考”的回应

3.1 如何从模糊需求提炼核心诉求？

先区分使用场景、底层目标、明确约束和主观偏好，忽略客套与无关描述。“夏天背舒服一点”保留为减少闷热、改善背负体验的偏好，不直接等同某个重量或专业护脊效果。“通勤”只说明使用场景，不等于带电脑；“女生用”也不自动推断粉色、小容量或少女风。

3.2 如何把口语映射为结构化筛选条件？

明确必备要求用于筛选；“最好、尽量”和舒适感等偏好用于排序，不能替代硬性条件。

消费者表达处理方式
“上班用，200 元以内”场景为通勤；预算不超过 200 元。
“至少 20L，最多 25L”同时设置容量下限与上限。
“要装 14 寸电脑”筛选电脑适配；仍需核对电脑外壳与内仓尺寸。
“必须宽肩带、尼龙面料”肩带结构与面料作为必选条件。
“夏天舒服点，最好宽肩带”透气、背负舒适与宽肩带作为偏好，不承诺不闷、不勒。
“不带电脑了，其他不变”删除电脑相关要求，保留其他条件，后续不自动恢复。

品类、容量、背负结构、面料、功能和场景共同参与匹配；明确数字不由模型随意改写，缺失属性不冒充满足要求。

3.3 如何多轮追问并澄清歧义？

优先确认场景，再确认主要装载物、必要容量或电脑尺寸等关键条件，然后补充预算与背负、防水偏好。每轮只问一个关键问题，提供快捷选项；已明确或跳过的信息不机械重复。

“这款”指向多款商品时先请用户选定；“第二款”按当前展示顺序识别。容量“至少 30L、最多 10L”等冲突会暂停推荐，说明冲突并让用户取舍，不自行猜测或放宽条件。无匹配时告知当前限制，只有用户确认调整后才更新筛选。

3.4 如何处理答错、幻觉与推荐不准？

先筛选、再生成说明，确保回答、卡片、参数和商品入口对应同一款。单品问题先回答问题本身；常见属性直接读取商品资料，不重复整段介绍。没有资料支撑的参数、售后或功能明确告知无法确认，不新增猜测的规格、好评率或链接。

评价以已有样本为依据，客观呈现正反反馈，不把个别观点扩大为整体结论。已对常见表达、多轮修改和界面流程进行回归检查，但复杂口语与主观风格仍可能误解；用户可通过明确补充条件或重新选定商品纠正。当前不承诺所有自然语言表达均能正确理解。

4. 商品数据与可信边界

当前内置 64 个互不重复的模拟商品条目，覆盖双肩包及少量托特包、斜挎包、胸包。图片、店铺、规格、价格、销量与评价用于体验流程，不代表真实在售商品、实测背负感或商家承诺；页面统一说明其模拟性质。三视图为生成的款式图片，不是商家实拍。

正式使用需接入公司自身商品数据库及授权接口，以真实 SKU 统一关联标题、规格、图片、价格、库存、评价和详情链接，并持续更新。模拟字段必须被真实资料替换；真实数据缺失时保持未知。

当前内置商品外部入口为同名搜索，不能保证搜索结果就是同款。只有录入准确链接后才能直达对应商品。部分评论可在页面查看；完整评价需在真实对应商品页核对。当前不支持订单、支付、实时全网比价或真实库存保证。

5. 运行延迟与 Token 费用

网页部署于 Render 免费实例。闲置后服务可能休眠，首次重新访问可能等待约 50 秒或更久；服务唤醒与模型生成是两个不同阶段。网络、服务负载及模型状态也会影响响应速度。如暂时无响应，可稍后刷新或重试，避免连续重复发送。

模型服务使用 DeepSeek。需要模型理解或生成内容的对话会消耗 Token，费用由配置在服务端的 API 账户承担；共用网页的访问者会使用同一账户额度。消耗取决于输入、必要上下文和输出长度，按服务商实际计费规则结算，当前不提供固定单次费用保证。

浏览页面、查看详情与已有评价、操作购物车、读取本地历史本身不消耗模型 Token；部分常见属性问答可直接读取资料。会话记录保存在当前浏览器；需要模型处理时，相关输入与必要上下文会发送至模型服务，请勿输入敏感个人信息。

6. 后续迭代方向

优先接入真实商品、库存与评价数据，持续增加真实消费者表达的测试样本；逐步改善复杂指代、风格偏好与冲突澄清。后续可增加语音输入、图片上传识别、账户同步与用量管理，这些功能当前尚未上线。

本作品用于展示 AI 导购的交互与决策辅助流程。真实选购请以经核对的商家商品资料为准。
